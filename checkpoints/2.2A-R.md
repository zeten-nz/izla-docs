## Canonical registry
- **Location:** `src/content/activity/activity-registry.ts` (`activity-registry-v1`, TD-246). Pure module — no Nest module,
  no DB/HTTP. Neutral content domain, not under any controller/HTTP layer.
- **Shape:** `ActivityDefinition { type, executionKind (OBJECTIVE|VIEW_ONLY|UNSUPPORTED), completionEvidence
  (SUBMITTED_ATTEMPT|COMPLETED_ACTIVITY|UNSUPPORTED), scoring (DETERMINISTIC_OBJECTIVE|NONE), learnerProjection
  (OBJECTIVE_SAFE|METADATA_ONLY), payloadContract (LESSON_OBJECTIVE_V1|NONE_DEFINED) }`. `ACTIVITY_REGISTRY:
  Record<ActivityType, ActivityDefinition>` + `getActivityDefinition` + predicates `isObjectiveActivityType` /
  `isViewOnlyActivityType` / `isUnsupportedActivityType` + derived `OBJECTIVE_ACTIVITY_TYPES` / `VIEW_ONLY_ACTIVITY_TYPES`.
- **Exhaustiveness:** compile-time (`Record<ActivityType,…>` — a new enum value without a row fails `tsc`) **and** runtime
  (test AR-01: `Object.values(ActivityType)` == registry keys, each exactly once; no "unknown → probably unsupported" fallback).

## Lesson objective payload authority
- **Location:** `src/lesson-execution/activity/objective-activity-payload.ts` (single implementation; unchanged public
  contract `lesson-activity-objective/v1`, error `ActivityPayloadInvalidError`, `projectActivityForLearner` strips
  `answerKey`). `parseObjectiveActivityPayload` now checks its schemaVersion + choice format, then delegates the structural
  rules to the shared primitive, passing its own `fail`. Its `OBJECTIVE_ACTIVITY_TYPES`/`isObjectiveActivityType` are
  **re-exported from the registry** (no local literal).

## Assessment separation (what is shared vs deliberately separate)
- **Shared:** ONLY the neutral low-level structural primitive `src/common/payload/choice-question-payload.ts`
  (`validateChoiceQuestionBody`) — prompt/options/answerKey/correct-count rules identical to both prior in-domain loops.
- **Deliberately separate (NOT shared):** schemaVersion (`lesson-activity-objective/v1` vs `placement-item/v1`), error
  class (`ActivityPayloadInvalidError` vs `AssessmentConfigurationInvalidError`, preserved by each wrapper passing its own
  `fail`), `open_ended` policy (assessment-only), learner projections, and lifecycle. AssessmentItem is NOT made "just
  another Lesson Activity" and does NOT import the registry. `placement-item/v1` remains its own versioned contract.

- **LessonExecution** (`lesson-execution.service.ts`): `projectActivity` + `persistAttempt` use
  `getActivityDefinition(type).executionKind === 'OBJECTIVE'` (was `isObjectiveActivityType`). Same behavior; same

- **Completion eligibility** (`lesson-completion-eligibility.ts`): `computeEligibility` uses `isObjectiveActivityType` /
  `isViewOnlyActivityType`; local `OBJECTIVE_TYPES`/`VIEW_ONLY_TYPES` removed. `lesson-completion.service.ts` uses

- **Daily-mission** (`daily-mission.policy.ts` `isObjectiveActivityType`; `daily-mission.repository.ts` `[...OBJECTIVE_ACTIVITY_TYPES]`),

  `.repository.ts` `[...OBJECTIVE_ACTIVITY_TYPES]`) — all sourced from the registry.
- **Scorer** (`objective-activity-scorer.service.ts`): UNCHANGED — registry says WHAT capability; scorer owns HOW (10000 bp
  correct / 0 incorrect, no partial credit, no AI).
