## Auth (unchanged backend contract, TD-251)
- **Access token = memory only** (`lib/auth/token-store.ts`): never localStorage/sessionStorage/IndexedDB/cookie/URL/persisted
  store. Refresh token = browser-managed HttpOnly cookie `izlan_refresh`; refresh uses `credentials: include` + `X-Izlan-CSRF: 1`.
- **Bootstrap** (`AuthProvider`): one `POST /auth/refresh` → `GET /auth/me` before deciding auth state (a missing in-memory
  token pre-bootstrap is not logout).
- **Single-flight refresh** (`lib/api/client.ts`): concurrent 401s share ONE refresh promise; each request retries at most
  once; a failed refresh does not loop; never a parallel rotation. No state-changing mutation auto-retries a 409/OCC.
- Logout clears the in-memory token + calls `/auth/logout`.

## CMS capability endpoint (backend addition)
- **`GET /api/staff/content/session`** (`CmsSessionController`, requires `content.author`) → `{ userId, capabilities:
  { author, publish, subjectManage } }`, derived from effective permission codes. Returns NO role names / PII / unrelated
  permissions / raw UserRole rows. author-only → publish=false/manage=false; METHODIST → publish=true; ADMIN →
  publish=true/manage=true; learner/no `content.author` → 403; unauthenticated → 401.
- Frontend uses these booleans for UX visibility ONLY; the backend stays the final authorization authority (SubjectAssignment
  scope re-enforced per mutation). **No role-name hard-coding** in the frontend (asserted by test WEB-06).
