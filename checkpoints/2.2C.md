## Auth (unchanged backend contract, TD-251)
- **Access token = memory only** (`lib/auth/token-store.ts`): never localStorage/sessionStorage/IndexedDB/cookie/URL/persisted
  store. Refresh token = browser-managed HttpOnly cookie `izlan_refresh`; refresh uses `credentials: include` + `X-Izlan-CSRF: 1`.
- **Bootstrap** (`AuthProvider`): one `POST /auth/refresh` → `GET /auth/me` before deciding auth state (a missing in-memory
  token pre-bootstrap is not logout).
- **Single-flight refresh** (`lib/api/client.ts`): concurrent 401s share ONE refresh promise; each request retries at most
  once; a failed refresh does not loop; never a parallel rotation. No state-changing mutation auto-retries a 409/OCC.
- Logout clears the in-memory token + calls `/auth/logout`.

## CMS capability endpoint (backend addition)
- **`GET /api/staff/content/session`** (`CmsSessionController`, requires `content.author`) → `{ userId, capabilities:
  { author, publish, subjectManage } }`, derived from effective permission codes. Returns NO role names / PII / unrelated
  permissions / raw UserRole rows. author-only → publish=false/manage=false; METHODIST → publish=true; ADMIN →
  publish=true/manage=true; learner/no `content.author` → 403; unauthenticated → 401.
- Frontend uses these booleans for UX visibility ONLY; the backend stays the final authorization authority (SubjectAssignment
  scope re-enforced per mutation). **No role-name hard-coding** in the frontend (asserted by test WEB-06).

## Auth amendment (TD-252 — phone + password primary login)
- **Schema/migration:** ONE new table `password_credential` (`user_id` PK 1:1 → `app_user` ON DELETE CASCADE,
  `password_hash` = Argon2id encoded PHC string). Migration `20260822120000_password_credential`. No destructive change;
  `User.passwordCredential` is nullable — legacy OTP-only users have none and cannot password-login until set/reset.
- **Password:** `Argon2PasswordHasher` port (`@node-rs/argon2`, Argon2id 19 MiB / t=2 / p=1) — encoded hash only; `verify`
  never throws. Policy 8..128, no composition rules, never trimmed (`assertPasswordPolicy`). Frontend mirrors the bounds.
- **Endpoints:** `POST /auth/login {phone,password}` (primary); `POST /auth/register {challengeId,code,password}` (verified
  REGISTRATION OTP → atomic User+Profile+LEARNER+credential → session); `POST /auth/password/reset {challengeId,code,
  password}` (verified PASSWORD_RESET OTP → credential upsert → **revoke all user sessions**); `otp/request` now carries
  `purpose` (REGISTRATION default / PASSWORD_RESET). The OTP-login endpoint is removed. `refresh`/`logout`/`logout-all`/`me`
  unchanged.
- **Enumeration + timing safety:** unknown phone / no credential / wrong password → ONE generic `401
  AUTH_INVALID_CREDENTIALS` (a dummy Argon2 verify equalizes timing on the miss path); SUSPENDED/DEACTIVATED denied only
  after a correct password (403). Safe security events (`password_login_success/failed`, `registration_success`,
  `password_reset_requested/success`) — never the password/OTP/token. `lastLoginAt` stamped on login.
- **Password-login rate limiting = DB-backed / cross-process (security correction):** authority is the append-only
  `SecurityEvent` table (`password_login_attempt`) — no new schema — so it survives restarts and is shared across
  PM2/multi-instance workers. Per attempt: ONE transaction acquires deterministic-ordered Postgres advisory locks (no
  deadlock) → counts window attempts by IP + phone → denies at the limit, else records one attempt → commits → then Argon2
  verifies (so concurrency cannot overshoot). The raw phone is NEVER a key — only an HMAC-SHA256(pepper, domain+phone)
  fingerprint; malformed phone → IP-only (no global invalid-phone bucket). The in-memory limiter is retained only for
  `otp/request` (NOT the password-login authority).
- **Password reset = atomic (security correction):** credential upsert + revoke-all `AuthSession` + revoke-all
  `RefreshToken` + `password_reset_success`/`all_sessions_revoked` events all commit or roll back in ONE transaction
  (shared `SessionsService.revokeAllUserSessionsInTransaction`, reused by logout-all) — a stolen refresh never survives a
  reset; a credential change never commits if revocation fails. Hashing stays outside the tx.
- **Dev tooling:** `ConsoleSmsAdapter` (`SMS_DRIVER=console`; production startup FAILS) prints only phone+purpose+code.
  `npm run db:seed:demo` (prod-refused, `ALLOW_DEMO_SEED=true`, env passwords via the production hasher, idempotent) seeds
  demo Admin (+998900000001) + Methodist (+998900000002) + `english-demo` DRAFT subject, both assigned (real authz model).
- **Web login:** `/staff/login` is phone + password with an accessible show/hide toggle (`autocomplete=current-password`),
  a **forgot-password OTP recovery flow** (phone → reset code → new password → back to sign in), and a dev-only demo helper
  (`NEXT_PUBLIC_ENABLE_DEMO_ACCOUNTS`, never production) that fills the **phone only** — never the password, never
  auto-login. uz/ru/en chrome. Access token stays memory-only; single-flight refresh unchanged.
- **Tests:** unit `PWD-01..05` (hash≠plaintext, verify, wrong-fails, salted, policy). e2e `AUTH-PWD-01..09`
  (login/wrong/unknown/passwordless-legacy same 401, suspended denied, phone normalization, lastLoginAt, refresh-after-
  login, logout), `REG-PWD-01..03`, `RESET-PWD-01..05`, `DEMO-01..06`, plus secret-hygiene. Web `WEB-AUTH-PWD-01..07`
  (phone+password required, OTP not in login, show/hide, generic error, forgot flow, uz/ru/en) — `WEB-AUTH-PWD-04`
  memory-only token is the WEB-01 token-store test — and `DEMO-WEB-01..03` (hidden by default, shown when enabled, fills
  phone only). **Security correction:** `RATE-PWD-01..07` (state survives instance recreation; two instances share the DB
  counter; persistent phone + IP limits; concurrent final-slot serialization; malformed phone consumes IP budget; no raw
  phone/password in metadata — HMAC fingerprint only) and `RESET-ATOMIC-01/02` (revoke-failure rolls the credential back;
  success atomically revokes all sessions + tokens with the events).
